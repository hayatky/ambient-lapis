# Ambient Lapis 要件メモ

作成日: 2026-07-18
更新日: 2026-07-19
ステータス: 初期要件確定

関連資料: [技術調査・構成メモ](./technical-research.md)

## 1. 目的

Nature Remo Lapisから自室の温度・湿度とエアコンの設定状況を定期的に取得してデータベースへ保存し、スマートフォンやPCから、分かりやすく、美しく、見やすく確認できるWeb UIを開発する。

本システムは個人的な趣味のために使用する。業務利用や一般公開は想定せず、必要以上に複雑な構成や商用レベルの完全性は求めない。一方で、日常的に眺めたくなるようなデザイン品質にはこだわる。

## 2. 基本方針

- Nature Remo Cloud APIを使用する。
- 温度・湿度・エアコン状態を既定5分間隔で収集する。
- 収集間隔は環境変数`POLL_INTERVAL`で変更できるようにする。
- 収集処理はWeb UIへのアクセス有無に関係なく常時動作させる。
- 収集データはSQLiteへ保存する。
- 収集・保存・内部APIはGoの常駐サービスが担当する。
- Next.jsはWeb UIを担当する。
- Docker Composeで運用する。
- Synology NASまたはHyper-V上のUbuntu Serverへ配置する。
- 初期版はLAN内からの個人利用に限定する。
- 機能を増やしすぎず、安定した収集と優れた閲覧体験を優先する。

## 3. 実現すること

### 3.1 データ収集

- Nature Remo Cloud APIへ既定5分間隔でアクセスする。
- 収集間隔は環境変数`POLL_INTERVAL`で変更可能とし、未設定時は5分とする。
- Nature Remo Lapisから次の情報を取得する。
  - 温度
  - 湿度
  - 温度の計測時刻
  - 湿度の計測時刻
  - Nature Remoのオンライン状態
- 登録された対象エアコンについて、次の情報を取得する。
  - ON/OFF
  - 運転モード
  - 設定温度
  - 風量
  - 上下風向
  - 左右風向
  - 状態更新時刻
- エアコン状態は、実機からの双方向取得値ではなく「Nature Remoが認識している状態」として扱う。
- 取得時刻と、Nature APIが返す計測・更新時刻の両方を記録する。
- 一時的なネットワークエラーやAPIエラーが発生しても、収集サービスを終了せず次回以降の取得を継続する。
- 最終取得成功時刻を記録する。
- APIのレート制限を超えないようにする。

### 3.2 データ保存

- 取得した情報をSQLiteへ保存する。
- コンテナを再起動・更新してもデータを保持する。
- 長期間の履歴を保存する。
- 時刻は内部ではUTCで保存し、Web UIでは日本時間で表示する。
- 温度と湿度の計測時刻は個別に保存する。
- 簡単なバックアップを作成できるようにする。
- SQLiteファイルは収集・内部APIサービスだけが直接扱う。
- SQLiteファイルをSMB、CIFS、NFSなどのネットワークファイルシステム上へ直接配置しない。

### 3.3 現在値の表示

- 現在の温度を大きく見やすく表示する。
- 現在の湿度を大きく見やすく表示する。
- Nature Remoのオンライン状態を表示する。
- データの最終取得成功時刻を表示する。
- センサー値の計測時刻を表示する。
- 最終取得成功が途切れた場合は、通常表示と明確に区別して警告する。
- センサーの計測時刻は表示するが、値が変化せず計測時刻だけが古いことを異常と推測しない。
- Nature Remoがオフラインの場合は警告する。

### 3.4 エアコン状態の表示

- エアコンのON/OFFを表示する。
- 運転モードを表示する。
- 設定温度を表示する。
- 風量と風向を表示する。
- 状態の最終更新時刻を表示する。
- 表示値が「Nature Remo認識状態」であることが分かるようにする。
- 状態が古い場合や不明な場合は、推測でON/OFFを表示せず`不明`として扱う。

### 3.5 履歴表示

- 温度と湿度の推移をグラフで表示する。
- 次の期間を簡単に切り替えられるようにする。
  - 直近24時間
  - 7日間
  - 30日間
  - 任意期間
- 表示期間に応じてデータを適切な粒度へ集計する。
- エアコンのON/OFF区間を温湿度グラフと関連付けて確認できるようにする。
- 日ごとの最低・最高・平均温度を確認できるようにする。
- 日ごとの最低・最高・平均湿度を確認できるようにする。
- データ欠損区間を、値が継続していたように誤表示しない。

### 3.6 Web UI

- スマートフォンとPCの両方で快適に閲覧できるレスポンシブUIとする。
- スマートフォンでは片手でも主要情報を確認しやすくする。
- PCでは画面の広さを活かし、現在値、履歴、エアコン状態を俯瞰できるようにする。
- 既存の通常表示に加え、温度・湿度・Nature Remo認識設定温度のグラフを主役にした専用キオスク表示を提供し、相互に移動できるようにする。
- キオスク表示はスマートフォン、タブレット、PCのいずれでもスクロールなしの1画面へ収め、現在値、エアコン認識状態、収集状態、グラフ、主要操作を同時に確認できるようにする。
- キオスク表示の既定期間は直近24時間とし、24時間、7日、30日を切り替えられるようにする。任意期間と日次サマリーは通常表示で扱う。
- キオスク表示ではグラフ上の時刻をマウス、タッチ、キーボードで選択し、温度、湿度、Remoオンライン状態、エアコン認識状態、認識設定温度を詳細表示できるようにする。
- キオスク表示でも「Nature Remo認識」であることを短い常設ラベルで明示し、実機状態と誤認させない。
- ダークモードへ対応する。
- 読み込み中、データなし、エラー、オフライン、収集停止の各状態を適切に表現する。
- グラフのツールチップや期間選択を、タッチ操作とマウス操作の両方で利用できるようにする。

### 3.7 運用

- Docker Composeで起動できるようにする。
- Synology NASまたはUbuntu Serverで動作できるようにする。
- Web UIへのアクセスがなくてもデータ収集を継続する。
- コンテナ再起動後に自動的に収集を再開する。
- Nature APIトークンをブラウザへ公開しない。
- Nature APIトークンをソースコードやGitへ保存しない。
- エラー内容をコンテナログから確認できるようにする。
- healthcheckにより、サービスが動作しているか確認できるようにする。
- 初期設定は環境変数またはsecretファイルで行えるようにする。

## 4. デザイン要件

デザイン品質は本システムの重要要件とする。単に情報が表示できるだけの管理画面にはせず、日常的に開きたくなる、上質で美しいプロダクトを目指す。

### 4.1 目標とする印象

- 高級感がある。
- 静かで落ち着いている。
- 洗練されている。
- 情報量があっても雑然と見えない。
- Apple製品のUIに見られるような、明快さ、余白、精密さ、自然な動きを参考にする。
- Appleの画面をそのまま模倣せず、このダッシュボード固有の表現を作る。
- 既製の管理画面テンプレートをそのまま使用したような見た目にしない。
- 安価なIoT製品の付属画面のような印象にしない。

### 4.2 視覚設計

- 十分な余白を取り、情報の優先順位を明確にする。
- 現在の温度・湿度を最も重要な情報として扱う。
- タイポグラフィのサイズ、太さ、行間を丁寧に設計する。
- 色数を抑え、必要な状態や温度感を色で表現する。
- グラデーション、半透明、ぼかし、光沢は控えめかつ意図的に使用する。
- ガラス表現を多用せず、可読性を損なわない範囲に限定する。
- 角丸、罫線、影、背景の階層を一貫させる。
- 装飾よりも、数値、グラフ、空間構成そのものの美しさを優先する。
- 温度、湿度、エアコン状態の色表現を全画面で統一する。
- ライトモードとダークモードの両方を個別に調整し、単純な色反転にはしない。
- キオスク表示は全画面背景としてグラフを配置し、現在値と状態を余白とタイポグラフィで重ねる。カードや長い注意書きを並べず、グラフと数字が最初に目へ入る構成にする。
- キオスク表示の操作menuはAmbient Lapisヘッダーの右側へ置くフラットな領域とし、面・ステータス行・罫線・角丸を持たせない。期間は`24h / 7d / 30d`の短いテキスト、テーマ・全画面・通常表示はアイコン主体の操作とする。初期状態では隠し、画面上のマウス移動・タッチ・キーボード操作時だけ一時的に表示する。390px前後のモバイルではbrandを隠して同じヘッダー行をmenuへ譲り、タブレット以上ではbrandとmenuを左右に同時表示する。操作が3秒間ない場合は自動的に隠し、操作部のhover / focus中は表示を維持し、`Escape`で閉じられるようにする。
- モバイルでmenuを表示している間はAmbient Lapisのbrandを隠し、操作領域と現在値の視認性を優先する。テーマ操作は3択のpopmenuとして開閉でき、キーボードの矢印キーと`Escape`で操作できるようにする。
- キオスクの選択時刻の詳細、履歴更新エラー、収集停止・Remoオフラインなどの重大警告は操作部と独立して表示し、操作部が隠れている間も確認できるようにする。

### 4.3 グラフ設計

- グラフは分析ツール然とした無機質な見た目にせず、画面全体のデザインへ溶け込ませる。
- 温度と湿度を容易に区別できる配色にする。
- エアコンON区間を背景帯などで美しく重ねる。
- 快適範囲を必要に応じて控えめに表示する。
- 目盛り、補助線、凡例は必要最低限に抑える。
- 数値を読み取れる精度と、全体傾向を眺めやすい美しさを両立する。
- 長期間表示では集計値を用い、線や点が過密にならないようにする。
- データ欠損は線を途切れさせるなど、正直に表現する。

### 4.4 インタラクション

- アニメーションは短く自然にし、操作を邪魔しない。
- 画面表示時の過剰な演出を避ける。
- 状態変化は色だけに依存せず、文字やアイコンでも伝える。
- ボタンや期間選択には、押せることが分かる適切なフィードバックを持たせる。
- タップ領域を十分に確保する。
- OSの`prefers-reduced-motion`を尊重する。

### 4.5 デザイン受け入れ基準

- スマートフォンとPCの両方で、主要情報を迷わず確認できる。
- 最初に現在の室内状態が目に入り、次に変化の傾向とエアコン状態を理解できる。
- 余白、文字、色、角丸、影、グラフ表現に一貫性がある。
- ライトモードとダークモードの双方で十分な可読性がある。
- UIコンポーネントを並べただけのテンプレート的な見た目になっていない。
- 警告表示が通常時の上質さを壊さず、それでも確実に認識できる。
- 実装後にスマートフォンとPCの実画面を確認し、視覚的な違和感を調整する。
- キオスク表示は390×844、768×1024、1440×900の各viewportで縦横スクロールが発生しない。通常時はグラフと主要オーバーレイを優先し、操作部は操作時だけ表示する。
- キオスク表示の通常、収集停止、Remoオフライン、不明、データなし、履歴エラーが、情報を捏造せず簡潔に識別できる。

## 5. 余裕があれば実現すること

次は初期版の必須要件とせず、後から追加できるものとする。

- 絶対湿度の表示
- 露点温度の表示
- 不快指数の表示
- 推定WBGTの表示
- 結露リスクの表示
- 快適範囲のグラフ表示
- エアコンのモード別運転時間
- エアコンの1日あたりON時間
- CSVエクスポート
- 温湿度や収集停止に関する簡単な通知
- TailscaleまたはVPNを利用した外出先からのアクセス
- Matterを利用したLAN内での直接収集

## 6. 実現しないこと

初期版では次を対象外とする。

- Nature Remoからエアコンを操作する機能
- エアコンの実消費電力の計測
- コンプレッサーが実際に動作しているかの判定
- Nature Remoが認識できなかった赤外線操作の補完
- 秒単位のリアルタイム監視
- Nature Homeに保存されている過去データの取り込み
- Lapisに搭載されていないCO2、照度、人感、PM2.5などの取得
- 一般公開
- 複数ユーザー向けのアカウント管理
- 権限・ロール管理
- 商用レベルの高可用性
- 複数サーバーによる冗長化
- PostgreSQLやRedisなどの追加ミドルウェア
- ネイティブiOS・Androidアプリ
- 複雑な通知・自動化ルール
- AIによる予測
- AIによるエアコン自動制御
- 電気料金や節電効果の厳密な計算
- 初期版でのMatter収集

## 7. 初期版の完成条件

次を満たした時点で初期版を完成とする。

- Docker Composeで起動できる。
- Web UIへのアクセスがなくても収集サービスが動作する。
- 既定5分ごとに温度・湿度・エアコン状態がSQLiteへ保存され、`POLL_INTERVAL`の変更が反映される。
- コンテナ再起動後も過去データが残る。
- スマートフォンとPCから現在の温度・湿度を確認できる。
- 温度・湿度の履歴をグラフで確認できる。
- エアコンのNature Remo認識状態、モード、設定温度を確認できる。
- オフラインやデータ取得停止に気付ける。
- Nature APIトークンがブラウザへ露出しない。
- UIがレスポンシブに動作する。
- ライトモードとダークモードが利用できる。
- 通常表示を維持したままキオスク表示へ移動でき、キオスク表示から通常表示へ戻れる。
- キオスク表示がスマートフォン、タブレット、PCの1画面へ収まり、24時間、7日、30日の履歴と選択時刻の詳細を確認できる。
- ありきたりな管理画面ではなく、上質で美しいデザインとして仕上がっている。
- スマートフォンとPCの実画面でデザインを確認し、主要な視覚上・操作上の問題が解消されている。

## 8. 初期前提

- 利用者は本人のみとする。
- 初期版はLAN内からアクセスする。
- LAN内利用のため、初期版ではアプリ独自のログイン機能を設けない。
- 外出先からのアクセスが必要になった場合は、アプリ独自認証より先にTailscaleやVPNを検討する。
- エアコンはNature Homeへプリセット家電として登録済みであることを前提とする。
- Nature Remo Lapisがエアコン付属リモコンの赤外線を受信しやすい位置に設置されていることを前提とする。
